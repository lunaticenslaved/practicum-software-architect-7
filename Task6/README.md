# Задание 6. Автоматическое обновление базы знаний

Скрипт `update_index.py` автоматизирует процесс обновления базы знаний:
сканирование источника, обнаружение изменений, синхронизация, чанкинг,
генерация эмбеддингов, обновление FAISS-индекса и логирование.

## Источник данных

**Папка `Task6/docs/`** — симулирует внешний источник документов (локальная папка,
S3-бакет, Git-репозиторий, RSS-фид и т.д.).

Подхват новых файлов: при каждом запуске скрипт сканирует `docs/` и сравнивает
SHA-256 хеши файлов с манифестом предыдущего запуска (`Task6/manifest.json`).
Обнаруженные изменения:
- **Новые файлы** — появились в `docs/` с прошлого запуска
- **Изменённые файлы** — содержимое изменилось (хеш не совпадает)
- **Удалённые файлы** — были в манифесте, но отсутствуют в `docs/`

Затем изменения синхронизируются в `Task2/knowledge_base/` (целевая БЗ).

### Пример: добавление нового документа

```bash
# 1. Положить новый файл в docs/
cp new_article.txt Task6/docs/

# 2. Запустить обновление
make update-index
```

## Структура файлов

| Файл / Папка | Описание |
|--------------|----------|
| `update_index.py` | Скрипт инкрементального обновления индекса |
| `crontab` | Готовая cron-задача для периодического запуска |
| `docs/` | Папка-источник (симулирует внешний источник данных) |
| `docs/Shadowfen.txt` | Пример документа — деревня Shadowfen |
| `docs/Crystal_Peaks.txt` | Пример документа — горный хребет Crystal Peaks |
| `manifest.json` | SHA-256 хеши файлов docs/ с последнего запуска (создаётся автоматически) |
| `logs/` | Папка с лог-файлами |

## Архитектура

```
Task6/docs/*.txt                    ← Источник данных (симуляция)
        │
        ▼
Task6/update_index.py               ← Скрипт обновления
        │
        ├── 1. Сканирование docs/   SHA-256 хеши всех *.txt
        ├── 2. Сравнение            manifest.json ↔ текущее состояние docs/
        ├── 3. Синхронизация        docs/ → Task2/knowledge_base/
        ├── 4. Чанкинг              Только новые/изменённые файлы
        ├── 5. Эмбеддинги           Только новые чанки
        ├── 6. Обновление индекса   FAISS IndexFlatIP
        └── 7. Логирование          Консоль + файл + JSON-резюме
        │
        ▼
Task2/knowledge_base/               ← Обновлённая база знаний
Task3/faiss_index/                  ← Обновлённый индекс
Task6/logs/last_update_summary.json ← Структурированное резюме
Task6/logs/update_*.log             ← Детальный лог запуска
```

## Периодический запуск (cron)

### Как запускать задачу

Файл `Task6/crontab` содержит готовую cron-задачу:

```cron
# Обновление базы знаний каждый день в 06:00
0 6 * * * cd /home/tek-gal/study/practicum-software-architect-7 && .venv/bin/python Task6/update_index.py >> Task6/logs/update.log 2>&1
```

### Установка

```bash
crontab Task6/crontab
```

### Как часто работает

Задача запускается **каждый день в 06:00** по серверному времени.

Расписание cron `0 6 * * *`:
- `0` — минута (0-я)
- `6` — час (06:00)
- `* * *` — каждый день, каждый месяц, каждый день недели

### Что происходит при ошибке

1. **Логирование ошибки**: скрипт перехватывает все исключения через `try/except`,
   записывает полный traceback в лог-файл и JSON-резюме со статусом `"ERROR"`
2. **Код выхода**: при ошибке скрипт возвращает код `1` (успех — `0`)
3. **Вывод в лог**: stdout и stderr перенаправляются в `Task6/logs/update.log`
   через `>> Task6/logs/update.log 2>&1` в crontab
4. **JSON-резюме**: файл `Task6/logs/last_update_summary.json` содержит поле
   `"error"` с описанием ошибки — можно использовать для мониторинга

### Удаление cron-задачи

```bash
crontab -r
```

## Логирование

### Что выводится в лог

| Информация | Пример |
|------------|--------|
| Время запуска | `2024-01-15 06:00:00 [INFO] Обновление базы знаний — старт` |
| Количество файлов | `Изменения в docs/: +2 новых, ~1 изменённых, -0 удалённых` |
| Синхронизация | `Добавлен → KB: New_Village.txt` |
| Количество новых чанков | `Чанкинг завершён: 12 чанков из 2 файлов` |
| Прогресс эмбеддингов | `Эмбеддинги: 200/3662 (5.5%)` |
| Размер итогового индекса | `FAISS-индекс пересобран: 3674 векторов` |
| Время завершения | `Обновление завершено за 15.3 сек` |
| Ошибки (если были) | `Критическая ошибка: Connection refused` |

### Структурированное резюме (JSON)

После каждого запуска создаётся файл `Task6/logs/last_update_summary.json`:

```json
{
  "timestamp": "2024-01-15 06:00:15",
  "status": "OK",
  "duration_sec": 15.3,
  "files": {
    "added": 2,
    "modified": 1,
    "deleted": 0
  },
  "chunks": {
    "new": 12,
    "removed": 5,
    "total_index_size": 3674
  },
  "error": null
}
```

### Текстовое резюме в логе

В конце каждого запуска выводится блок:

```
============================================================
РЕЗЮМЕ ОБНОВЛЕНИЯ
============================================================
Статус:            OK
Время выполнения:  15.3 сек
Файлов добавлено:  2
Файлов изменено:   1
Файлов удалено:    0
Новых чанков:      12
Удалённых чанков:  5
Размер индекса:    3674
============================================================
```

## Совместимость

Скрипт полностью совместим с существующим пайплайном:
- Использует те же параметры чанкинга, что и `Task3/01_chunking.py`
- Использует ту же модель эмбеддингов, что и `Task3/02_embeddings.py`
- Записывает в те же файлы (`chunks.jsonl`, `embeddings.jsonl`, `index.faiss`, `metadata.json`)
- RAG-движок (`Task4/rag_engine.py`) подхватывает обновлённый индекс при следующем запуске
