# Задание 7. Аналитика покрытия и качества базы знаний

Оценка полноты БЗ через двухфазный прогон golden set (13 запросов) и JSONL-логирование всех запросов к боту.

## Двухфазный прогон

Скрипт `evaluate.py` выполняет два этапа с пересборкой FAISS-индекса:

| Фаза | Действие | Запросы |
|------|----------|---------|
| 1 — Absent | Удаляет 3 файла из БЗ → пересборка индекса → 5 absent-запросов (бот **не должен** ответить полно) | A1–A5 |
| 2 — Known | Восстанавливает файлы → пересборка индекса → 8 known-запросов (бот **должен** ответить) | K1–K8 |

Удалённые сущности: `Rift_of_Echoes.txt` (локация), `Valdric.txt` (персонаж), `The_Duskborne_Purge.txt` (событие).

## Golden Set

13 запросов в `golden_questions.json`: 8 known (K1–K8) + 5 absent (A1–A5).

Каждый запрос содержит ожидаемые ключевые слова и целевой файл-источник.

## Метрики

| Метрика | Описание |
|---------|----------|
| Keyword Coverage | Доля ожидаемых ключевых слов в ответе (0–100%) |
| Refusal Rate | Доля запросов с отказом бота |
| Retrieval Hit Rate | Доля запросов, где FAISS нашёл чанки из целевого файла |
| Avg Score | Средний cosine similarity найденных чанков |

## Результаты

**Общий результат: 10/13 (76.9%)**

| Группа | PASS | FAIL | Доля |
|--------|------|------|------|
| Known | 7 | 1 | 87.5% |
| Absent | 3 | 2 | 60.0% |

Провалы:
- **K2** — Obsidian Circle: бот ответил содержательно, но использовал другие формулировки (проблема выбора ключевых слов)
- **A3** — Duskborne Purge: бот ответил полно благодаря перекрёстным ссылкам в других файлах
- **A5** — Three Legends: coverage 80% — на границе порога, высокая связность БЗ

## Логирование запросов

Каждый запрос к RAG-боту сохраняется в `Task7/logs.jsonl` (append-mode).

Поля: `timestamp`, `query`, `chunks_found`, `has_chunks`, `answer_length`, `is_success`, `sources`, `elapsed_sec`.

Критерии `is_success`: найден ≥1 чанк, ответ >50 символов, нет маркеров отказа, нет ❌.

Реализация: метод `_log_query()` в `Task4/rag_engine.py`.
