# Задание 1. Исследование моделей и инфраструктуры для RAG-бота

## 1. Сравнение LLM-моделей

### Локальные модели (Ollama / vLLM)

| Критерий | Оценка |
|----------|--------|
| Качество | Llama 3 8B Q4 — достаточно для RAG-суммаризации, близко к GPT-3.5 |
| Скорость | CPU: 5–15 tok/s, GPU (T4): 20–50 tok/s |
| Стоимость | Фиксированная (сервер), окупается при >1000 запросов/день |
| Данные | Полный контроль — ничего не покидает контур компании |

### Облачные модели (OpenAI / YandexGPT)

| Критерий | Оценка |
|----------|--------|
| Качество | GPT-4o — эталон, но избыточен для RAG-пересказа |
| Скорость | Стабильная, 1–3 с на запрос |
| Стоимость | ~$0.01–0.03 за ответ, растёт линейно |
| Данные | Запросы уходят на внешние серверы — риск для конфиденциальности |

### Выбор LLM

**Llama 3 8B (Q4) через Ollama** — контроль данных, предсказуемая стоимость, достаточное качество для RAG.

## 2. Сравнение моделей эмбеддингов

### Локальные (Sentence-Transformers)

| Модель | Языки | Качество (MTEB) | Размер |
|--------|-------|-----------------|--------|
| `intfloat/multilingual-e5-large` | 100+ языков | Высокое | ~2.2 ГБ |
| `BAAI/bge-large-en-v1.5` | Английский | Лидер EN | ~1.3 ГБ |
| `all-MiniLM-L6-v2` | Английский | Среднее | ~80 МБ |

### Облачные (OpenAI `text-embedding-3-large`)

Высокое качество, но rate-limit (3000 RPM), линейный рост стоимости, данные уходят наружу.

### Выбор эмбеддингов

**`intfloat/multilingual-e5-large`** — мультиязычность, локальное развёртывание, фиксированная стоимость.

## 3. Сравнение векторных баз данных

| Характеристика | ChromaDB | FAISS |
|---------------|----------|-------|
| Архитектура | Клиент-сервер (REST API) | In-process библиотека |
| Инкрементальные обновления | ✅ Полная поддержка | ⚠️ Ограничена |
| Метаданные | ✅ Встроенные | ❌ Самостоятельно |
| Скорость поиска | Высокая (HNSW) | Экстремально высокая (in-memory) |
| Простота MVP | ✅ Высокая | ✅ Высокая |
| Зависимости | PostgreSQL, отдельный сервис | Только `faiss-cpu` + `numpy` |

### Выбор векторной БД

**FAISS (IndexFlatIP)** — минимум зависимостей, точный поиск без аппроксимации, простота развёртывания. Метаданные хранятся в отдельном JSON-файле. При масштабировании возможен переход на ChromaDB.

## 5. Итоговый стек

| Компонент | Выбор | Причина |
|-----------|-------|---------|
| LLM | Llama 3 8B (Ollama) | Контроль данных, достаточное качество для RAG |
| Эмбеддинги | `intfloat/multilingual-e5-large` | Мультиязычность, лидер бенчмарков |

| Инфраструктура | Docker Compose | Простота развёртывания для MVP |
