# Эмбеддинги и векторный индекс

## Выбранная эмбеддинг-модель

Для проекта QuantumForge Software выбрана модель **`intfloat/multilingual-e5-large`** на базе архитектуры XLM-RoBERTa, оптимизированная для задач семантического поиска и retrieval.

**Почему эта модель:**

- **Мультиязычность** — поддерживает 100+ языков, включая английский, финский, шведский и эстонский, что критично для финско-эстонской компании с мультиязычной документацией.
- **Качество** — лидер бенчмарка MTEB (Massive Text Embedding Benchmark) в категории мультиязычных моделей, показывает recall@10 > 0.90 на технических корпусах.
- **Размер эмбеддингов** — 1024 измерения, что обеспечивает высокую семантическую точность при индексации технической документации.
- **Локальное развёртывание** — модель работает полностью на своей инфраструктуре, исключая передачу конфиденциальных данных вовне (соответствие SOC 2 и GDPR).
- **Совместимость** — нативная интеграция с Sentence-Transformers и библиотеками LangChain/LlamaIndex.

| Характеристика | Значение |
|---------------|----------|
| **Название** | `intfloat/multilingual-e5-large` |
| **Репозиторий** | [Hugging Face — intfloat/multilingual-e5-large](https://huggingface.co/intfloat/multilingual-e5-large) |
| **Разработчик** | Microsoft Research / INT-Float |
| **Размер эмбеддингов** | 1024 |
| **Максимальная длина токенов** | 512 |
| **Размер модели** | ~560 МБ (2.24 ГБ в FP32) |
| **Архитектура** | XLM-RoBERTa Large |

**Особенность использования:** Модель требует префикса `query:` перед поисковыми запросами и `passage:` перед индексируемыми документами для оптимального качества retrieval.

## Векторный индекс (FAISS)

Для хранения и поиска по эмбеддингам используется **FAISS** (Facebook AI Similarity Search).

| Параметр | Значение |
|----------|----------|
| **Тип индекса** | `IndexFlatIP` (Inner Product) |
| **Метрика** | Cosine similarity (для L2-нормализованных векторов) |
| **Документов в индексе** | 3 655 |
| **Размер индекса** | 15 МБ (`faiss_index/index.faiss`) |
| **Метаданные** | 2.7 МБ (`faiss_index/metadata.json`) |

**Почему FAISS:**
- Экстремально быстрый поиск за счёт прямого доступа к памяти.
- Минимум зависимостей (`faiss-cpu` + `numpy`).
- Простота развёртывания — нет необходимости в отдельном сервисе.
- Персистентность через `faiss.write_index` / `faiss.read_index`.

## Запуск

```bash
# 1. Чанкинг + генерация эмбеддингов
make chunks

# 2. Создание FAISS-индекса
make index

# 3. Поиск по запросу
make search QUERY="Who is Toren Solwind?"
```
